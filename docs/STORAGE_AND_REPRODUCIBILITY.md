# Storage and reproducibility — alpha.8

Alpha.9 reuses the reviewed ceilings without increasing them. Perten's existing
499,245-byte original archive is verified against the official checksum; no raw
acquisition occurs. Public Datasets `build_canonical` writes one external shared
cache reproduction, with an original-ID reference adapter and content proof.
The first warning-only partial preparation is preserved separately. Datasets
does not silently promote it to computed. No upstream converter is executed or edited.

P1/P2, P3 and P4 use the existing journal; all four exact checkpoints reuse on
restart. A relative-library-path transport failure is retained as a failed P3
attempt before a successful retry; it is not a numerical candidate failure.
One 103-prediction native outer fold replays exactly. Supplementary association,
structure eligibility, Ridge and replay use the same per-task/campaign accounting.
Metric provenance is stored through the full-report digest rather than repeated
inside each compact metric. Metadata-proven unavailable designs do not reserve
nonexistent OOF arrays; attempted/failed designs remain recorded.

New portable exports of byte-identical comparison/admission/identity/replay files
share verified NTFS file identities with their local stage/input copies. Frozen
historical files are not changed. The combined unique task evidence is about
4.06 MB, below 4,194,304 bytes; on a fresh clone portable files alone occupy about
1.62 MB. Scientific scratch/full reports remain separate. See audit/alpha9-storage.json
for exact measured bytes; tooling/build changes are separate fixed costs. No raw
matrix is stored in the registry or copied per CV fold. Cache hashes and source/
provider/controller fingerprints are necessary for reconstruction; a compact
manifest alone does not promise replay under another numerical build.
The first secondary-family receipt estimated 12 fits; the eight actual outer
folds require 32 native inner/refit fits for the single fixed Ridge candidate.
The planner now derives that bound from the frozen folds. This is an explicit
compute-count correction, without numerical or byte-budget changes. Historical
supplement/Ridge receipts bind the driver at source commit `e711cc8`; that source
remains preserved in Git. The main executed bank controller still matches the
qualified wheel, and the four main checkpoints remain exact matches.
The preparation guard rechecks the admitted archive hash before any provider
write, binds cache proof to admission, and compares cached specimen keys, axis,
float32 X and permitted development Y directly to the original archive. It
never treats a cached intermediate Y as independent provenance. Estimates include
the external cache volume as well as the workspace. Original Perten data pass
this renewed verification without changing the frozen task; a changed-origin
fixture is refused before canonical writing.

Datasets 0.3.11 owns acquisition (`get`, `retrieve`, native `verify_cached`) and
canonical Parquet. Domains does not provide another downloader, canonical writer
or eviction engine. The native default on Windows is
`%LOCALAPPDATA%/nirs4all-datasets/cache`; `cache_dir` is an explicit provider option.
Existing alpha.4–alpha.7 local canonical reproductions remain at their original
locations. They are not silently migrated or advertised as hosted canonical data.
The pinned provider can load a local canonical reproduction with `get(root=...)`;
this local-first path requires our separate recorded hash verification.

The user reviewed measured free capacity and approved an alpha.8 campaign budget:
512 MiB incremental campaign reservation, one task at a time, 256 MiB incremental
per task, 4 MiB persistent evidence per task, 2 GiB free reserved on every volume.
These are local operating choices, not universal minimum capacities. The explicit
workspace ceiling adds 512 MiB to the measured starting footprint. Re-estimate
after tools/builds change. No destructive operation is implemented or authorized.

## Layers and evidence grades

| Layer / retention | Contents | Independent audit / replay |
|---|---|---|
| Datasets shared source/canonical | One verified content/source revision, raw origins separately when required | Access and license govern portability; identical spectra do not establish cross-dataset identities |
| `scratch` | Temporary complete task JSON required by current Rust ABI, mean export and intermediate native lineage | Per execution/stage/attempt; validated copies can be proposed for cleanup, never automatically deleted |
| `essential_evidence` | Task/config/content/provider hashes, exact OOF IDs/truth/predictions, fold IDs, scoped lineage digests, summaries, uncertainty, successful/failed attempts and limitations | Supports checking reported metrics; scope maps/models can require replay |
| `replay_checkpoint` | Optional selected models, full scoped target maps, verified immutable input refs | Local reconstruction only when authorized bytes and matching binaries remain available |
| `debug_archive` | Optional full logs, per-draw details and model payloads | Useful for debugging; not routinely copied into Git |

Replay grades are `metadata_only`, `reconstructed_from_cache`, and
`requires_authorized_origin`. A compact record alone cannot promise byte-identical
replay. Alpha.8 registers the frozen EcoSIS report and verifies representative
cells using its preserved local input; it does not acquire or republish raw data.
Optional gzip archives use mtime=0, empty filename, explicit level, and record
compressed/uncompressed SHA-256 plus zlib version; compressed bytes are only
guaranteed for that compressor version. No historical golden is recompressed.

## Budget, checkpoints and concurrency

`python -m nirs4all_domains.bank estimate --plan PLAN --policy POLICY
--workspace ROOT --scratch SCRATCH --evidence EVIDENCE` is read-only. It verifies
existing input hashes, counts each content once, reports expected fits/attempts,
scratch/evidence/peak bytes and checks every participating volume. Missing costs
remain uncertain; a declared dense float32 matrix is not a download-size promise.
Actual partial files remain charged. The scheduler intentionally supports one
concurrent task in alpha.8, enforced by a kernel file lock on the shared campaign
state root. Independent state roots are separate campaigns and must not be used
to bypass one workspace's budget. This is cooperative admission control, not an
OS filesystem quota against unrelated programs.

Per-task reservations accumulate across stages, and the persistent evidence cap
includes all successful stage records for that task. Existing referenced cache
files outside the workspace are included once in the working-footprint budget;
the available-space check also sees their occupied volume capacity. Repeated
execution versions remain charged until an explicitly approved retention action.

P0 inventory, P1 eligibility, P2 moderate characterization, P3 deep science and
P4 consolidation are separate journal entries. A stage reserves its predicted
peak before its callback; failed/crashed reservations remain charged. A restart
retries into a new attempt directory. Only validated, size-checked, checksummed
JSON is atomically published; a complete stage verifies its artifact on reuse.
Hashes of data/source/target/representation/dependencies/splits/preprocessing/
models/protocol/binaries/settings are part of the execution contract. Similar
RMSE does not authorize reuse. Estimates that underpredict scratch or evidence
fail explicitly; partial files remain accounted for and visible. Stage output is
bounded before publication. A native operation can allocate scratch during a
stage: this is monitored between stages, not an OS hard quota during a fit.

Cleanup is a **plan only**. Only explicitly owned, validated scratch with an
unchanged digest can be listed. Frozen alpha.4–alpha.7, shared caches, links,
running jobs, files referenced by other manifests and unknown files are excluded.
The caller must supply all campaign manifests/running roots. The CLI also loads
the frozen baseline list and excludes the entire historical results tree.
There is no deletion command. Any future cleanup/migration needs separate user
approval with exact paths, savings and replay implications.

The CLI requires an explicit `--shared-caches` machine-local JSON list, including
custom provider cache roots. Known default Datasets cache roots are protected even
when omitted from that list. A shared cache remains excluded even if a caller
incorrectly labels one of its files as owned scratch.

## Full-bank operating scenarios

Storage = reusable fixed tools/builds + distinct raw and canonical dataset bytes
+ retained evidence per qualified task + maximum concurrent scratch. Count
dataset-source revisions once, but count target/split/policy executions separately.
The catalog currently supplies 1,667 primary source/numeric-target templates;
representation and split alternatives increase that count. Inventory costs only
metadata. P1 requires rights/identity review before acquisition. P2/P3 are on demand;
alpha.8 does not schedule a full-bank scientific campaign.

Scenarios must substitute measured provider byte sizes for unknown raw/canonical
costs. For example 100 admitted tasks at 0.1–4 MiB retained evidence imply
10–400 MiB evidence, plus their distinct inputs and at most 256 MiB cooperative
scratch under this policy. This is a scenario, not a catalog forecast. A declared
50,000 × 512 × two-source entry alone has 204,800,000 float32 X bytes before
raw bytes, metadata or task JSON. It exceeds the qualified 500-row deep workflow;
no rows are silently discarded or scientific thresholds weakened to admit it.
