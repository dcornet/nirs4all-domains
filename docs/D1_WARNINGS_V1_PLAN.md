# D1 conditional structural warnings v1 — expected behavior before tests

The owning component is the optional Domains Python report interpreter, alongside
D2 validation intent and D3 comparisons. A content-bound sidecar consumes existing
JSON evidence through explicit pointers and renders JSON/Markdown. No diagnostic
kernel, loader, splitter, fitted model, default report rewrite or third crate.
Numerical evidence and predictions are unchanged. Research composes the owner API.

The pre-interface inventory audit found347 saved cases,78 recorded identities
(70 current canonical,8 historical),80 dataset/source X views,77 NIR identities
and1 MIR outgroup.62 recorded NIR provenance components are not databases or
independent experiments. Datasets' actual descriptor schema has no authoritative
original-database ID; original references are retained and that count is unknown.
Five named NIR factor datasets remain five identities despite multiple factor rows.

## Contract and deterministic decisions

Use the existing D2 pointer resolver, finite canonical JSON hashing and schema
validation conventions. The additive `domains.structural_warnings.v1` request
declares source/content/population/representation scope, provenance and bindings
to already measured evidence. Every binding must match the requested source,
population and representation; available native record fields are cross-checked.
Missing/invalid/nonfinite/stale/mismatched evidence is never promoted to a warning.
Declarations do not authenticate a provider or establish physical independence.

Five stable warning IDs cover physical units, experimental-factor geometry,
representation dependence, spectral support and missing context. Each record has
observation/provenance, conditional risk hypothesis, conditions/alternatives,
concrete checks/prerequisites, exact evidence scope, automatically assembled
dataset/view/source coverage and limitations. Status/reason/value expresses
computed versus unavailable assessment; computed values are qualitative
`observed`, `conditional` or `contradicted`, never scores, grades or probabilities.

- Physical dependence requires declared technical/shared specimen/reference
  evidence or a qualified existing Preflight finding. X clusters and sample-key
  counts alone never establish physical repeats. Known overlap can motivate a
  blocked new-unit contrast only for the corresponding deployment objective.
- Qualified non-Y descriptive factor-PC association is reported even when
  cluster ARI is weak/negative. Zero versus nonzero is an observed arithmetic
  condition, not an optimized threshold, significance or severity. Target-derived
  labels are excluded. Cardinality/missingness/repeats/confounding stay explicit.
  Factor exclusion is a conditional check, not a categorical-column LOGO rule.
- Representation changes are separated into PC variance, full-X neighbors,
  PCA neighbors, flat partitions and parameter sensitivity. Compare only
  predefined admissible, matched settings/populations/queries. Computed all-noise,
  trivial partitions and native refusals remain distinct. No favorable family.
- Support exceedance requires observed evaluation X and train-only fitting;
  positive count motivates an extrapolation check. Zero on PC1 does not establish
  multivariate coverage or unseen-future-population support. Counts are not risk.
- Missing context identifies which identities/acquisition/reference questions
  cannot be answered. It does not establish a dangerous dataset or reconstruct
  missing physical groups. Unknown intent produces conditional alternatives.

## Counterexamples and validation

Test UCPH batch eta/weak ARI, milk Cow_ID eta/nearly-zero ARI, cartilage preserved
neighbors/changed partitions, all-noise, missing physical IDs, known unit overlap
with new-unit intent, high PC1 alone, train-only PC1 exceedance, stable/negative
evidence, duplicated-Y metadata, crossed factors, unknown intent and stale/tampered
bindings. Test actual CLI/schema packaging and unchanged report numerics. Stored
public/native synthetic fixtures suffice; no real profiling/model fit is launched.

No statistical tolerance or warning severity cutoff is introduced: read stored
measurements, exact identity/parameter equality and mathematical endpoints0/1.

different named definition. The erroneous squared formula in the frozen R3d
candidate document receives an additive research erratum, not a historical edit.
