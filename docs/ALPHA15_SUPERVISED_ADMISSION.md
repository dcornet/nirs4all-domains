# Exploratory supervised admission — domains.confrontation.v0.1

Three outcomes are distinct: X-only characterization, keyed development-only XY
description, and exploratory supervised qualification. Publication permission
neither grants analysis permission nor establishes scientific independence.

X-only admission requires authorized analysis and qualified complete X. XY
description additionally requires verified original keyed X/Y correspondence,
target meaning/units and development scope frozen before target decoding.
Prediction further requires original study/specimen/reference/assay ownership,
a complete dependency map and feasible component-safe folds. Exact original,
canonical-X, canonical-Y and closure hashes bind a qualified task. Shared keys
cannot cross a component or partition. Unique observation IDs alone fail this
gate. The same original component must bind native validation membership.

A real execution also requires a separate owner-approved pilot ID, fit upper
bound and storage plan. The alpha.15 resource authorization explicitly excludes
that execution. The current source investigation does not produce a qualified
real freeze, and unavailable real outcomes remain unavailable.

The executable admission/freeze/execute APIs are tested on public synthetic
tasks using actual Methods/DAG selection and refit. They verify exact membership,
retained-label isolation, model/provider/freeze hashes, native grouped folds,
budget-before-fit and checkpoint recovery without refitting after retained-Y
mutation. These tests qualify software behavior rather than a real study.
