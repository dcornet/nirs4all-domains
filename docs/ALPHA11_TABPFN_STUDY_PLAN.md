The public nirs4all 1.4.10 `TabPFNNIRSRegressor` source from
1aefd473a0ebeef28adc0d808c4a4b0c9c45fa9f matches its wheel exactly. Audit only:
**TabPFN is not installed, no checkpoint is acquired, no estimator is fitted.**
Source performance claims are not local scientific qualification.

The wrapper uses SG(window11, poly2, derivative1), supervised OSC(component1),
an evenly spaced feature cap and train-fitted centering, then a 16-member
TabPFN ensemble. Its defaults are seed0, device `auto`, checkpoint `auto`, feature
cap2000 and `ignore_pretraining_limits=True`. Those last choices are not accepted
as evidence that a particular future checkpoint supports a task.

Before any later execution:

- Pin the exact TabPFN package, model generation, checkpoint filename/hash and
  availability. Audit weight-license acceptance and analysis/deployment/statistics
  publication rights separately from wrapper source rights.
- Qualify CPU/GPU feasibility, available memory, complete-population sample/feature
  limits, checkpoint/cache bytes, peak scratch and wall time. Review the budget
  before installation or weight acquisition. No timing is currently measured.
- Replace unversioned checkpoint/device selection. Record package, hardware,
  precision, RNG seeds, reproducibility tolerance and complete prediction lineage.
- Fit the entire supervised recipe independently inside each native inner-training
  scope and selected outer refit. OSC must never see outer validation or retained
  targets. Reuse training column indices and fitted transforms at prediction.
- Keep source/admission/folds fixed and compare task-wise PLS/Ridge and already
  qualified adaptive anchors where their exact protocols match. Do not select a
  source, preprocessing recipe or grid after observing TabPFN errors.

The future experiment asks whether structural sensitivity differs. It does not
assume that TabPFN uses more or fewer shortcuts. Empty candidate categories and
unidentified source populations remain visible rather than receiving substitutes.
