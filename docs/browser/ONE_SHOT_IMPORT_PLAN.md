# One-shot import: prospective technical contract and resource plan

Frozen before qualification implementation on 2026-11-18. Base is the qualified
worker-loading PR #15, `8549b2d87812afec65716e2256311624da67de3e`; main remains
`ada9ca3e44abf58011db5be04aadd580ada69e7f`. PR #16/F4.3 and its numerical/PDF
failures remain untouched. No scientific algorithm or protocol is changed.

## Expected behavior

One file/folder submission starts IO/Formats inference, validation and assembly.
Valid unambiguous inputs open the actual LocalDataset without a required global
review, confirmation checkbox or second import action. Import performs no fit.
Existing Rust guards independently admit each later diagnostic population.

IO owns delimiter, columns, missing tokens, types, identities and joins. A
successful native assembly is necessary but not sufficient when its semantics
contradict Domains: never guess positional joins, merge independent X blocks,
invent partitions, impute, aggregate, remove observations or drop empty bands.
Unknown evidence stays unknown. No arbitrary confidence score is introduced.

Import does not execute IO validation-fold declarations. They stay in the
original session/specification; the validated assembly projection excludes
fold configuration and explicitly inactive sources. This also prevents an
ancestor folder name containing `fold` from blocking ordinary X/Y/M loading
through IO 0.2.14's broad convention match. Relative filenames, source roles,
partitions, axes and all bytes stay unchanged. No fold/split is created, used
for fitting or declared qualified by this projection. CSV parser edits are
re-materialized through IO before role selectors are rebuilt from actual owner
headers; no JS delimiter parser or missing-value converter is introduced.

An unresolved Y/M attachment may be retained separately while independently
validated X is opened. Original files/declarations remain in the session and
the restriction is explicit; detached tables never masquerade as aligned Y/M.
Blocking ambiguities ask only their necessary role/key/partition/CSV questions.
The existing shared DatasetBuilder is an optional advanced editor before or
after import; applying edits revalidates IO and replaces dataset provenance.
Dependent live diagnostics are invalidated only after a successful replacement.
Failed replacement leaves earlier validated data/results available.

Missing X/Y/M, entirely missing declared variables and all observations/axes
are retained. No Y-to-M conversion, target decoding outside IO semantics or
global complete-case filtering. Report JSON remains distinct from data/config.
Session-only files are reread when needed; transferred buffers are never reused.
READY/bootstrap/cancellation/timeouts/stale-response and data-free diagnostics
from #15 remain mandatory. No IndexedDB/raw-data persistence is added.

## Qualification expectations

Use synthetic/public fixtures and actual published IO/Formats in a built Vite
app under `/nirs4all-domains/`: single/multiple/combined X/Y/M, keyed reordered
tables, directories, explicit/absent partitions, mixed/multiple/missing targets,
partial/all-missing M, unresolved attachments, duplicate/ambiguous keys,
incompatible X blocks, CSV correction, provenance replacement, cancellation,
worker failures/recovery, saved reports and unchanged historical reports.
Expected negative cases remain visible; role and missingness receipts are exact.
Normal imports need one submission and no additional confirmation. All numeric
predictions/metrics and F4.0–F4.2 fitting/access policies are unchanged.
Windows/Ubuntu plus Chromium/Firefox, EN/FR, keyboard and automated accessibility
must have execution evidence. Mocks alone cannot qualify the import path.
