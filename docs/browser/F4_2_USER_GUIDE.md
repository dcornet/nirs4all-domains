# F4.2 train reference and test positioning

Import the original X/Y/M files through the reviewed IO workflow. Declare train and test partitions, axes and observation identities. F4.2 is an explicit operation in step 2 of the existing four-step journey; opening a dataset or changing language does not run it.

Select the train projection dimension and, if desired, the separate monitoring parameters before execution. The explicit starting values are 2 projection components, a maximum of 2 monitoring components, 5 folds and alpha 0.05. These are starting settings, not a test-selected optimum. Inadmissible settings are refused locally by Rust/Methods; the interface never changes folds or parameters to obtain a result. Each execution appends a new result and provenance. Earlier F4.0/F4.1 results remain available. Cancellation terminates the worker and obsolete replies cannot replace newer results.

Train circles are teal; test squares are orange. Axes name the actual informative score columns reported by the provider. A single nonconstant returned display coordinate uses a horizontal rail; the rail is not PC2. Numerical rank resolution is unavailable from this API. FlexiblePCA explained variance is unavailable from the public API. Component dispersions are owner Methods summaries, not substituted eigenvalues. No metadata coloring is added to this projection. Existing F4.1 factor colors retain their separate permissions.

Projection and T²/Q monitoring use distinct Methods protocols and provenance. Raw train-reference/test-query neighborhoods remain an independent F4.0 operation. Neither proximity nor PCA position establishes support, predictive performance, physical identity or leakage probability.

Monitoring tables retain all returned reference/test T²/Q values, empirical thresholds, exceedance/near-limit counts, centroid measures and numerical conditions. Thresholds remain descriptive unless the runtime reports `conditional_external`; the current interface supplies no external qualification record. The provider folds rows by index modulo the requested fold count. Missing identities do not establish independence; repetitions and shared groups can prevent qualification. Alpha is not a coverage guarantee.

Reports use the existing HTML, Markdown and JSON model. Mandatory evidence retains statuses, reasons, receipts, qualification, limitations and complete returned scientific support objects. The PCA figures and documentary tables remain selectable annexes. No raw X, Y or observational M vector is added; score coordinates and technical observation keys are retained. Saved historical reports are not rewritten or recalculated.

English and French interface readings are available. Source reasons, method names, parameters and provenance remain exact. Read unavailable reasons before interpreting partial results; no replacement coordinates or statistics are generated.

Local request or transport failures use `domains.browser_train_fitted_support_local_refusal.v1`, a documentary UI protocol distinct from the strict runtime result. They carry a null evidence hash and no successful provider execution or owner certification is inferred. The strict runtime result schema applies only to actual runtime results.
