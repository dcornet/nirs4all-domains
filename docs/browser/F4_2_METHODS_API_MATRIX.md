## FlexiblePCA behavior from pinned implementation

The installed TypeScript declaration is in `bindings/wasm/node_modules/@nirs4all/methods/dist/estimatorRolesGenerated.d.ts` (`FlexiblePCAParams`, `FlexiblePCA`, default `n_components: 5`); `NativeEstimator` lifecycle/serialization is in `dist/estimatorRoles.d.ts`; the class and method ID are in `dist/estimatorRolesGenerated.js`. The pinned source is `cpp/src/core/preprocessing/feature_selection/flexible_pca.c` and `.h` at the commit above. The fitting algorithm documented there is column-centering followed by an SVD, with canonicalized signs and variance divisor `n_samples - 1`; transform is `(X - mean) @ components.T`. There is no feature scaling, whitening, or learned scaling factor.

Component selection: an integer-valued `n_components >= 1` requests that count, clamped to `min(rows, cols)`. A value strictly between 0 and 1 selects the smallest prefix whose cumulative variance ratio reaches that value. The C interface accepts a `double`; for count mode the implementation casts to integer, so a consumer should pass an integer count rather than rely on fractional values above 1. The default is 5. The estimator does not expose a solver parameter. Although the source file's introductory comment describes full SVD, the fit implementation selects exact/truncated paths or a randomized truncated path based on shape and count; the public fitted state and `transform()` result do not report which path was used. Do not claim the consumer selected an exact solver.

Fit requires at least 2 rows and 1 feature. A failed refit leaves prior estimator state intact at the generic estimator API. For rank-deficient or constant data the estimator's count mode still follows requested/clamped width; zero-variance columns/components are not returned with Preflight's unresolved flags. In variance-ratio mode a zero-total-variance fit has all explained-variance ratios zero; no prefix reaches a positive requested ratio, so the implementation's fallback retains `min(rows, cols)`. It does not define a numerical-rank contract. Consequently, returned width and any independently summarized score dimensions must remain distinct from spectral rank and variance qualification. A model-state digest covers the serialized mean/components/parameters, not source rows or spectral dispersion.

## `statsPcaMonitor` precise contract

**JavaScript:** `statsPcaMonitor(reference, monitored, maxComponents, nFolds, alpha)` in the pinned `dist/preflightDiagnostics.d.ts` and `.js`; the wrapper calls public C symbol `n4m_stats_pca_monitor`. **Catalog ID:** `diagnostics.pca_monitor` (`catalog/methods/diagnostics.pca_monitor.yaml` at the pinned commit). The native signature is:

```c
n4m_status_t n4m_stats_pca_monitor(
  n4m_context_t *ctx,
  const n4m_matrix_view_t *reference,
  const n4m_matrix_view_t *monitored,
  int32_t max_components,
  int32_t n_folds,
  double alpha,
  double *eigenvalues,
  double *reference_t2,
  double *reference_q,
  double *monitored_t2,
  double *monitored_q,
  int32_t *effective_components,
  int64_t *out_counts,       /* 6 entries */
  double *out_thirteen       /* 13 entries */
);
```

Native dimensions: `n_reference >= 3`, `n_monitored >= 1`, `p >= 1`, equal feature count; `2 <= n_folds <= n_reference`; `0 < alpha < 1`; `1 <= max_components <= p` and `max_components <= n_reference - ceil(n_reference/n_folds) - 1`. Invalid dimensions/parameters are `N4M_ERR_INVALID_ARGUMENT`. Nonfinite or out-of-domain values are rejected; the numerical domain is finite values, each nonzero magnitude in `[2^-256, 2^256]`, and max/min nonzero magnitude spread at most `2^32`. More than 50 million combined cells or 10 billion estimated operations yields `N4M_ERR_UNSUPPORTED` before allocation. Downstream fold/full PCA failures are returned as errors.

Fold assignment is fixed by row position: fold `f` holds reference rows `i` where `i % n_folds == f`; each fold model trains on all other reference rows. Reference row `i` is evaluated under fold `i % n_folds`. This accepts no group-aware or declared fold identities. Every fold and the full-reference model centers on its own fit rows. The effective component count is the smallest resolved numerical rank among fold and full fits, capped at `max_components`; resolution is `16 * max(n_reference, p) * eps * lambda_1`.

For centered row vector `x`, `T² = sum(t_a² / lambda_a)` over effective components; `Q` is squared Euclidean norm of the explicit residual after projecting onto the effective subspace. The T² and Q limits are empirical type-7 quantiles at `1-alpha` of all out-of-fold reference T²/Q values, not a parametric control limit. `tau = 16 * max(n_reference,p) * eps * condition`, where `condition = lambda_1/lambda_k` of the full fit. A monitored row is beyond T² by more than `tau * max(row_T², T²_limit)` or beyond Q by more than `tau * max(row_norm², largest_reference_centered_norm²)`. Within the tolerance band is counted as `near`, not as beyond; equality at the lower tolerance edge is classified at-or-below. T² is NaN when no effective components resolve; Q remains defined from the full centered row. For one monitored row, `monitoredTotalVariance` is NaN because sample variance requires at least two rows. The tolerance is documented as a conservative estimate, not a certified bound; empirical tail fractions are descriptive and few reference rows yield coarse limits.

The native `out_thirteen` order is `[t2Limit, qLimit, referenceTotalVariance, monitoredTotalVariance, centroidDistance, centroidSubspaceDistance, centroidResidualDistance, centroidT2, retainedFraction, tolerance, condition, qToleranceScale, eigenvalueResolution]`. `out_counts` is `[nBeyondT2, nBeyondQ, nBeyondEither, nNearT2, nNearQ, nNearEither]`. The JS wrapper maps these into the camelCase keys listed in the callable matrix; its typed declaration is the authority for JS key spelling.

## `preflightPca` and neighbor distinction

`preflightPca(X,k)` is exported separately from `FlexiblePCA`. It calls `n4m_preflight_pca_compute_resolved`: requires `n >= 2`, `p >= 1`, `1 <= k <= min(n,p)`, and the narrower PCA diagnostic numerical range documented in `cpp/include/n4m/metrics.h` (nonzero magnitudes `[2^-128,2^128]`, spread `<=2^32`). This ABI computes a centered covariance decomposition by exact Gram eigendecomposition, publishes full-spectrum moments despite truncation, and reports an absolute eigenvalue resolution and unresolved flags. Thus it is appropriate only where a one-shot full diagnostic is explicitly requested; it is not a serialization/query-transform seam for the train-fitted estimator.

`preflightNearestNeighbors` is independent of PCA. It accepts any equal-width query/reference matrices and exposes optional cross-group exclusion, deterministic tie order, and missing-neighbor sentinels. Since it gets no observation IDs, row groups, axes or provenance beyond the optional group arrays, identity matching remains the caller's responsibility.
