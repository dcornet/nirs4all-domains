# Product–research boundary

Revision: 2026-10-28. This is an ownership/documentation transition, not a new
numerical protocol or execution authorization. Baseline inspected locally and on
GitHub: `5b0354a236318e42188a17f9703363a33e6df706`.

Domains diagnoses spectral organization, support and validation limitations.
The proposed `nirs4all-structural-research` program investigates mechanisms and
remedies using those diagnostics. Neither needs to wait for the other: X-only
diagnostics are useful without H1–H5 confirmation, and experimental findings do
not automatically become generic product behavior.

## Ownership matrix

| Responsibility | Domains product | Future research repository / model ecosystem |
|---|---|---|
| Structural characterization | Qualified protocols, source/view identity, axes and evidence states | Consume evidence for questions and experiments |
| Multi-scale X structure | Qualified generic descriptors and limitations; audit existing providers first | Test correspondence with nested/crossed factors and scientific mechanisms |
| Source/split support and proximity | Dependency guards, neighborhoods, overlap/extrapolation and uncertainty scope | Compare scientifically selected deployments and interventions |
| Validation intent/applicability | Population, unit/group basis, unseen context, supported/unsupported claims | Register research contrasts and inferential assumptions |
| Generic group/cluster diagnostics | Documented-factor evidence, X structures and their association/unknown correspondence | Establish whether observed structure explains additional predictive dependence |
| Representation sensitivity / metadata corroboration | Qualified descriptive comparisons, without invented nuisance identities | Test mechanisms and representation remedies |
| Model-result interpretation | Read-only compatible source/target/split/pipeline outcomes and limitations | Comparative model robustness, effect estimates, falsification and publication |
| Hypotheses and registries | Link to preserved evidence; do not make hypotheses compulsory product behavior | Prospective hypotheses, controlled studies and experimental registries |
| Cross-database inference | Supply traceable diagnostics; no automatic population inference | Database/dependency-aware statistics, multiple comparisons and confirmation |
| Synthetic Y and weak injected group signals | No new product feature in this assignment | Null calibration and mechanism experiments |
| Synthetic spectra / augmentation | Describe input/protocol effects when qualified | Physical, simulated, conditional/generative augmentation studies |
| Self-supervised / invariant representations | Generic diagnosis only where qualified | Experimental learning and cost to genuine chemistry |
| Hierarchical/local experts | Interpret supplied compatible results | Soft/hierarchical mixtures, RF/XGBoost routing, TabPFN/TabICL local-expert hypotheses |
| Reusable estimators / numerical kernels | Call public providers; do not duplicate them | New estimators belong primarily in appropriate upstream model/Methods packages |
| Reporting and continuity | Stable contracts, explicit evidence, public references and reproducibility | Import read-only evidence; keep separate analysis registries and publication outputs |

Datasets retains catalog/content/cache/access ownership; Formats/IO retains vendor
decoding; Preflight retains intrinsic qualification; Methods retains generic
numerical kernels; DAG/model APIs retain fitting/selection execution. Domains
does not become a repository for every speculative predictive method. No upstream
repository is changed or authorized for editing by this transition.

## Evidence vocabulary

| Level | Meaning | What Domains can say |
|---|---|---|
| Structural observation | Measured X property | Report geometry, memberships, continuity/density, representation and uncertainty scope without Y |
| Validation concern | Source, dependence, proximity, grouping, support or split property affecting interpretation | State the concern and its consequence for a specified use; unknown correspondence stays unknown |
| Empirical sensitivity | Estimator/pipeline response to a compatible protocol change | Report errors, null comparison, support, populations, effect and uncertainty limits |
| Scientific mechanism hypothesis | Proposed explanation, including shortcut reliance | Link to the hypothesis and controlled evidence; do not infer it from association alone |
| Validated interpretation | Independently supported conclusion with established inferential scope | Link to the specific evidence and applicability; do not generalize beyond the tested population/shift |

The first three are generic diagnostic outputs. The last two require separately
supported evidence. Observation, confidence, consequence and action remain
explicit. Absence of validated shortcut evidence is not absence of product
functionality. There is no universal shortcut percentage, deployment-quality
label or compulsory low-risk certificate.

## Method promotion rule

A candidate method needs all of the following before consideration for generic
Domains functionality:

1. A clear objective and legitimate generic diagnostic use.
2. Controlled-case validity, including relevant leakage/identity adversaries.
3. Documented benefits, null results and failure modes beyond one favorable dataset.
4. Stable computational bounds and public provider/source/ABI/binding requirements.
5. Explicit limitations, uncertainty and deployment applicability.
6. Reproducible qualification and a versioned compatibility decision.

Scientific success alone does not mandate product implementation. Predictive
estimators generally belong upstream even after research success; Domains may
interpret their results through a stable evidence contract. A method that merely
suppresses clustering has not thereby improved generalization.

## Continuity and immediate scope

The [read-only interface and transition](RESEARCH_INTEROPERABILITY_AND_TRANSITION.md)
uses existing evidence formats and immutable references. The separate repository
name is a proposal: no repository is created, private evidence moved, raw data
copied or new artifact publication authorized. Historical public artifacts stay
in place. Ordinary source-permitted aggregates do not acquire a new privacy gate
merely because a catalog marks a dataset private.

The [product D1–D5 roadmap](ROADMAP.md) and [research R1–R5 program](STRUCTURAL_GENERALIZATION_RESEARCH_PROGRAM.md)
have distinct completion criteria. [Validation intents](VALIDATION_INTENTS.md)
describe deployment questions; [multi-scale and augmentation notes](MULTISCALE_AND_AUGMENTATION_NOTES.md)
separate implemented fields, planned generic interpretation and speculative remedies.
No experimental real/synthetic fitting, VAE, expert tree, GPU setup, recursive
clustering framework, new global result schema or numerical implementation is
introduced in this assignment. Existing regression/package/CI checks remain.

[Transition validation evidence](audit/product-research-transition-review.json)
records the actual local checks, package parity and preserved-file scope; completed
final-commit CI is verified separately from its configuration.
