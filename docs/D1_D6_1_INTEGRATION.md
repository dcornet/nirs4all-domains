# D1-D6.1 integration on the current public baseline

This integration branch brings the qualified warning/reporting features onto
`main` baseline `d5de755856ce15aea9f24f2750e92a45eaac3a12`. It is a source
integration, not a new scientific campaign or a release/version change. The
existing D2/D3 implementations and selected-branch persistence descriptor are
already part of that baseline; they are not reimplemented here.

The historical feature chain is `6645b1e` (D1 warnings), `a481ecc` (D4 standalone
consumer), `4150214` (D5 presentation), `4df5d5f` (D6 readiness) and `5bdfecf`
(D6.1 optional decision reading). Their original commits and source-hash-bound
patches were checked before cherry-picking. Conflicts in the architecture and
method-reuse introductions preserve both the newer upstream-alignment notes and
the additive feature descriptions. No scientific source/schema conflict or
opportunistic numerical change is introduced.

## Included behavior

- [D1 warnings](STRUCTURAL_WARNINGS_API.md): five conditional families, with
  computed, conditional, contradicted and unavailable evidence kept distinct.
- [D4 standalone consumer](STANDALONE_REPORT_API.md): source-validated offline
  HTML, Markdown and JSON, without changing the original reports or Preflight.
- [D5 decision context](D5_WARNING_UTILITY.md): intended population, prediction
  unit and actual split; historical 18/20 qualification retains both manure
  prerequisite-state mismatches rather than redefining them as passes.
- [D6 readiness](VERIFICATION_READINESS_API.md): separate observation, inputs,
  protocol, authorization and exact receipt-backed execution. A documentary
  receipt cannot establish that a broader scientific analysis was performed.
- [D6.1 reading](DECISION_SUMMARY_API.md): optional `--decision-summary`, separating
  density parameters, spectral representation and neighborhood comparisons, with
  documentary actions and conditional deployment questions. Default historical
  serialization and all original companion contracts remain compatible.

Eight dataset identities/views in the prior research qualification do not prove
eight independent studies or original databases. Original database grouping and
physical/reference independence remain unknown where not established. No human
review or user-effectiveness result is inferred from automated contract tests.

## Baseline preservation and verification

The current `CECILL-2.1 OR AGPL-3.0-or-later` licence, package versions, Cargo.lock,
provider/dependency alignment and scientific changes from the public baseline
are retained. Methods owns numerical operations, Preflight intrinsic validation,
and Domains the conditional interpretation. No other repository is modified.

The existing `scientific-gates` workflow remains enabled with its full native,
schema, registry and synthetic integration gates. The additional
`warning-report-contracts` workflow validates the pure reporting path without
optional numerical providers and exercises only public/synthetic examples in
offline desktop/mobile browsers. No private Research reports, raw X/Y matrices,
expert-review materials or local journals are copied into this public checkout.
Both workflows prepare the additive interpretation schemas before building the
installed bridge. On Windows, the historical structural-warning generator uses
platform line endings while newer generators explicitly use LF; preparing them
before packaging keeps installed/source schema mirrors byte-consistent through
the later regeneration gates. No schema definition or numerical value changes.
Historical evidence remains historical; actual execution for this integrated
tree is recorded in the pull request and the separate private integration audit.

No source-dataset fitting, new PCA/HDBSCAN characterization, preprocessing
optimization, resampling, D7 development or acquisition is part of this task.
The existing hosted synthetic/native engineering tests may exercise their
original numerical fixtures; those are not new research observations.
Local native rebuilds are separate from hosted CI and are not claimed when not
executed. A pushed branch or opened PR does not update `main`; merge requires
the owner's separate explicit approval.
