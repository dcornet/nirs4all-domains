## What is actually established

The public [Domains demo](https://dcornet.github.io/nirs4all-domains/) uses real
Methods-backed Rust/WASM, published IO/Formats import and shared UI. Main's
[scientific](https://github.com/dcornet/nirs4all-domains/actions/runs/43508124497),
[report](https://github.com/dcornet/nirs4all-domains/actions/runs/43508124550),
[browser](https://github.com/dcornet/nirs4all-domains/actions/runs/43508124482)
and [Pages](https://github.com/dcornet/nirs4all-domains/actions/runs/43508124463)
workflows succeeded on that exact commit. An additional public Chromium
desktop/mobile smoke passed 25 checks: actual synthetic computation, IO CSV,
four WASM assets, intended-use purity, retained-partition refusal, isolated JSON
report reading, theme/language, exports/offline print, cancellation and explicit
invalid-input refusal. No HTTP/console/page error or external/upload request was
observed. CI additionally exercised Firefox WASM; the public smoke did not.

Four common native/WASM fixtures establish cross-platform/provider transport
agreement under explicit tolerances, complemented by rank-one analytical
expectations. They do not independently validate every covariance spectrum,
ill-conditioned input, HDBSCAN interpretation or future deployment population.

Historical descriptive evidence establishes that neighborhood preservation,
partition stability, factor association and support are distinct properties.
These observations can motivate conditional checks. They do not establish a
calibrated failure probability, causal shortcut, universal validation protocol,
preprocessing winner or demonstrated benefit to users.

## What remains uncertain

The corpus has repeated cases/views/targets and incomplete original-study and
physical/reference identity closure. Its independent-study denominator is
unknown. D5's simulated scenarios and D6.1's AI non-blinded review are software
and presentation evidence; genuine human judgments remain zero. R3c/R3d preserve
unfavorable and estimator-dependent prospective results, too few external
families, weak-baseline and discovery-complexity limitations. Additional X views
cannot repair those limitations by increasing an apparent sample count.

The native product already has train-only projection/support seams. The
browser's full-X diagnostics do not expose a fitted state for projection of
retained observations. This review proposes preconditions and tests; it does
not implement a second PCA or fit concatenated train/evaluation populations.

## Phase 1 outcome and immediate priorities

Targeted changes enforce the existing analytical tolerance, reject malformed
neighbor ordering/padding without repairing it, and correct stale architecture
and hosting documentation. Ordinary provider outputs and historical reports
are not rewritten. See the corrective branch's checks for execution on its
exact source; baseline CI and new tests must not be conflated.

Next: validate the bounded train-only protocol, improve the explanation of
missing metadata and supported claims, and obtain an independent assessment of
actionability using existing expert materials. Any new real-source contrast
requires a separate content-bound freeze and explicit owner authorization.
